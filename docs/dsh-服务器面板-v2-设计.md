# dsh-server-panel v2 设计（产品视角）

> 一句话定位：**"不用 SSH，也能把这台服务器管住"** —— 面板是给人用的运维控制台，不是把命令行的输出抄到网页上。

---

## 1. v1 的问题（先承认）

| # | 问题 | 用户实际感受 |
|---|---|---|
| 1 | **权限是残的**：文件管理永远以 `$USER` 身份跑，`/etc` 下的配置、root 的日志、`/root` 一律碰不到 | "我解锁了 sudo，为什么还是改不了 nginx 配置？" |
| 2 | **信息架构是平铺的**：三个标签页，一屏塞满卡片，没有"这里出事了"的引导 | "我要自己从 200 个服务里找哪个挂了" |
| 3 | **操作都要跳页**：看服务日志要展开列表、看文件要切换标签、确认框打断流程 | "点了半天才回到刚才的地方" |
| 4 | 缺三个高频能力：终端、软件包、网络 | "还是得回去开 SSH" |

v2 的目标就是把这四条堵死。

---

## 2. 用户与场景

**用户**：你。单台 Debian 服务器（4 核 3.8G、纯命令行、无图形界面），从另一台电脑经 SSH 隧道访问 DSH Web UI。
**你真正想干的事只有四类**：

1. **看**：现在这机器健康吗？有没有东西挂了？（3 秒内要有答案）
2. **救**：某个服务不对 → 重启它 → 看它到底报了什么错（30 秒内闭环）
3. **改**：改一个配置文件 / 传一个包上去（不离开浏览器）
4. **装**：打安全更新、装个软件（一次点完，别让我拼命令）

---

## 3. 设计原则

1. **首屏回答"有没有问题"**：异常浮到最上面，正常的东西折叠起来。
2. **操作不跳页**：详情用右侧抽屉，列表就地展开，结果就地反馈。
3. **权限是一个开关，不是一个谜题**：顶部常显"当前身份"，一键解锁/锁定，解锁后**所有模块都变成 root**，不再逐模块解释。
4. **危险的事要"减速"不要"禁止"**：写系统目录、重启 ssh、卸载软件包 → 明确的二次确认 + 影响说明；其余操作零摩擦。
5. **只展示真实存在的东西**：没装 docker/ufw 就不出现空模块，而不是给一个空白页。
6. **诚实**：数据来自 `/proc`、`systemctl`、`ss`、`apt`；拿不到就说拿不到，不做估算。

## 4. 信息架构（v2）

```
┌ 服务器面板 ─────────────────────────────────────────────────────────────┐
│ 顶栏： your-host ● 健康(1异常) │ 🔎 命令面板 ⌘K │ 🔓 root: 未解锁 │ ⟳ 2s │
├────────┬──────────────────────────────────────────────────────────────┤
│ 左导航 │  内容区（每页都是"概览卡 + 可操作列表 + 抽屉详情"三段式）      │
│  总览  │                                                              │
│  服务  │                                                              │
│  文件  │                                                              │
│  日志  │                                                              │
│  终端  │                                                              │
│  软件包│                                                              │
│  网络  │                                                              │
└────────┴──────────────────────────────────────────────────────────────┘
```

### 各页职责

| 页面 | 首屏回答 | 主体 | 详情（不跳页） |
|---|---|---|---|
| **总览** | 这机器现在健康吗？ | ① 异常横幅（failed 服务 / 磁盘 >85% / 内存 >90% / 负载超核数 / 有安全更新）② 4 个 KPI 大卡（CPU / 内存 / 磁盘 / 负载，带迷你趋势）③ 常用服务快启（可收藏）④ 最近事件流 | 点任意卡片 → 右侧抽屉给出细节 |
| **服务** | 哪些在跑、哪些挂了 | 分组标签（失败/运行中/已启用/全部）+ 搜索 + 行内动作 | 抽屉：状态、**日志实时跟随**、依赖、最近重启、自启开关 |
| **文件** | 我要找/改的文件在哪 | 左目录树 + 右列表（名称/大小/时间/权限/属主）+ 常用路径书签 + root 模式开关 | 就地大编辑器（Ctrl+S 保存、冲突提示）；系统目录写入二次确认 |
| **日志** | 刚才发生了什么 | 单元/关键字/时间范围过滤，**实时跟随**开关，行数控制 | 就地展开单条上下文 |
| **终端** | 我要敲命令 | 全宽终端（真 PTY），普通/root 切换，多会话标签，复制粘贴 | — |
| **软件包** | 有没有要打的更新 | 可升级列表（名称/当前→候选）+ 一键全部升级 + 索引更新时间 | 抽屉：包详情；单包升级 |
| **网络** | 谁在监听、连着哪 | 网卡卡片（IP/速率）+ 监听端口表（协议/地址/进程）+ 已建立连接 Top | 抽屉：按进程聚合的连接 |

### 命令面板（⌘K / Ctrl+K）

输入即搜：`重启 cron`、`看 ssh 日志`、`打开 /etc/nginx`、`打更新`、`终端` —— 一个输入框覆盖 80% 的高频操作，这是"少点几下"的核心杠杆。

## 5. 权限模型 v2

```
未解锁 ──[输入 sudo 密码]──▶ 已解锁（root 身份，可随时锁定）
  │                                │
  ├ 文件：白名单（~、/etc 只读等）  ├ 文件：全盘可读可写
  ├ 日志：仅本用户可见              ├ 日志：全量
  ├ 服务：只读                     ├ 服务：启停/重启/自启
  └ 软件包/终端：只读               └ 软件包：更新/升级；终端：可开 root shell
```

**规则**

- 顶部常显身份胶囊：`🔒 未解锁` / `🔓 root · 剩余 9:58`，点它解锁或立即锁定。
- 解锁后**所有模块**自动切到 root，不再逐模块判断；任何需要权限的操作在未解锁时**直接把密码框弹出来**，而不是回一句"权限不足"。
- **系统目录写入**（`/etc`、`/boot`、`/usr`、`/lib`、`/bin`、`/sbin`、`/var/lib`）必须二次确认，确认框里写清"这会改动系统配置，可能影响启动或服务"。
- 密码只写进 `sudo -S` 的 stdin / 由终端自己向用户索取；只存 dsh 进程内存；锁定、空闲 10 分钟、插件卸载即清除并 `sudo -k`。
- 端口仍只监听 `127.0.0.1`，走你的隧道；**不把 3080 暴露到局域网**。

## 6. 交互规范

- **抽屉（Drawer）**：从右侧滑入，宽 ~520px，不遮挡左导航；Esc 关闭；抽屉里的操作就地生效并刷新列表。
- **就地反馈**：每个动作在它发生的位置给一行结果（成功/失败原因），不用 `alert`，不跳页。
- **危险动作用"打字确认"或明确勾选**：重启 `ssh`/网络类单元、卸载软件包、删除目录 → 确认框里必须写清后果（例如"会切断你当前隧道"）。
- **加载与空状态**：骨架/占位文案 + 重试按钮；空列表说清为什么空（"没有失败的单元"优于空白）。
- **刷新节奏**：总览 2s、服务 5s、日志跟随 1s；切走即停；顶栏可暂停轮询（省电/省流量）。
- **键盘**：`⌘K` 命令面板、`g` 开头跳页（g o / g s / g f）、`/` 聚焦搜索、Esc 关抽屉。

---

## 7. 视觉规范

- 只用 `--dsw-alias-*` / `--dsw-elevation-*` 主题 token，亮/暗自动跟随，字号跟随 DSH 设置。
- 层级：**大数字（24–28px）> 卡片标题（13px 600）> 说明（12px 次级色）**；一屏内同类元素不超过 3 种字号。
- 状态色只用于状态：正常=中性/链接色、警告=warn、错误=error；**不要**把正常值涂绿。
- 密度：列表行 28–32px，卡片间距 12px，内容区左右 20px；窄窗口（<720px）时抽屉改为全屏覆盖。
- 图标：全部用内联 SVG 线条图标（不用 emoji），尺寸 14/16/18 三档。

## 8. 功能清单（v2 新增）

| 模块 | 能力 | 权限 |
|---|---|---|
| 终端 | 真 PTY（复用 dsh 自带 `subprocess.spawnTerminal`）、多会话、普通/root shell、resize、Ctrl+C | root shell 需 `sudo -i` 或已解锁 |
| 软件包 | 可升级列表（模拟 upgrade 解析）、单包/全部升级、`apt-get update` 刷新索引、已安装查询 | 升级与刷新需解锁 |
| 网络 | 网卡（`ip -j addr` + `/proc/net/dev` 速率）、监听端口（`ss -tulpn`，root 时带进程名）、已建立连接 Top | 进程名需解锁 |
| 文件（升级） | 全盘读写、chmod/chown、系统目录写入二次确认、常用路径书签 | 全盘读写需解锁 |
| 抽屉与命令面板 | 服务详情抽屉（含日志跟随）、⌘K 命令面板 | — |

## 9. 验收标准

1. 未解锁时：文件限制在白名单、服务只读、软件包只读；任何越权操作**直接弹解锁框**，解锁后自动重试成功。
2. 解锁后：能读 `/etc/ssh/sshd_config`、能写 `/etc/hosts.test`（二次确认）、`journalctl` 全量、`systemctl restart cron` 成功、`apt-get update` 成功。
3. 总览首屏 3 秒内能看出：failed 单元数、磁盘占用、内存、负载、可升级包数。
4. 服务抽屉里的日志**自动追加**（无需手点刷新），关掉抽屉即停。
5. 终端可用：`ls`、`systemctl status`、`apt list` 正常；root 切换后 `whoami` 输出 root；resize 生效。全屏 TUI（htop 类）不保证，界面明确标注。
6. 命令面板能用键盘完成"重启某个服务"和"跳到某个目录"。
7. 全部自动化测试通过；`install_bundle` 后热生效，`Slots` 显示两个槽位注册，路由未认证请求被栅栏挡下（401）。

---

## 10. 分期

- **v2.0（本轮）**：权限模型（全模块 root）+ 信息架构（左导航/顶栏/抽屉/命令面板）+ 总览/服务/文件重做。
- **v2.1**：终端（PTY + WebSocket）、软件包、网络三个新页。
- **v2.2**：日志页（跟随 + 过滤）、审计事件流、键盘快捷键补全。
- **v3（可选）**：容器、多主机 SSH、告警规则、把操作接给 AI 对话。
